# CimBar — Color Icon Matrix Barcode

[English](README.md) · **Русский**

CimBar превращает любой файл в анимированный GIF, каждый кадр которого — сетка цветных фигур-плиток, и восстанавливает файл обратно.

Попробуйте прямо сейчас: **https://nfcarchiver.com/cimbar/**

В репозитории:

- **`web-app/`** — веб-приложение, рассчитанное в первую очередь на телефон: отправляет и принимает штрих-коды CimBar прямо в браузере. Всё работает на стороне клиента — без сервера, без установки, данные не покидают ваше устройство.
- **`app/`** — приложение на Flutter для Android и iOS: отправляет (штрих-код на весь экран или GIF через «Поделиться») и принимает (живое сканирование камерой, фото или импорт GIF).

Каждая ячейка сетки несёт 6 бит данных: 2 бита выбирают один из 4 ярких цветов (зелёный, голубой, жёлтый, светло-пурпурный — RGB (255, 85, 255)), а 4 бита — одну из 16 фигур-плиток на чёрном фоне. Единый размер кадра 608 px вмещает четыре поисковых узора в стиле QR, по одному в каждом углу, так что декодер сразу находит сетку и её ориентацию — как с камеры, так и из точного изображения. В каждом кадре есть заголовок с порядковым номером и общим числом кадров. Файлы автоматически сжимаются, когда это выгодно, и могут быть зашифрованы AES-256-GCM перед кодированием — без пароля GIF не прочитать.

У больших файлов больше нет медленного непредсказуемого «хвоста»: помимо N кадров исходных данных, каждый штрих-код несёт дополнительные *восстановительные* кадры, полученные комбинированием исходных данных над конечным полем. **Любые N кадров — исходные или восстановительные, в любом порядке** — восстанавливают весь файл, поэтому декодер, ловящий кадры вразнобой (или пропустивший несколько), заканчивает примерно за столько захватов, сколько в файле кадров, а не ждёт, пока попадутся последние недостающие.

Это формат CimBar v2 (v2.1 добавляет сжатие и восстановительные кадры при той же геометрии кадра); он полностью заменяет исходный формат с 7 битами, 8 цветами и угловыми точками. **Файлы, закодированные до v2, нужно перекодировать**: GIF формата v1 не декодируются текущим приложением, а GIF из текущего приложения — приложением эпохи v1. Приложение чистой v2 (v0.9.1) ещё декодирует несжатый GIF v2.1 по его исходным кадрам, но сжатый — нет.

## Быстрый старт

Веб-приложение — это обычные HTML и JavaScript, без установки и сборки, но его нужно открывать по http(s): живое сканирование работает в Web Worker, который браузеры не запускают со страницы `file://`, а камере и Web Crypto нужен защищённый контекст (`https://` или `localhost`).

```bash
cd web-app
python3 -m http.server 8080
```

Затем откройте `http://localhost:8080` в браузере. Чтобы проверить камеру с телефона, раздавайте страницу по HTTPS или используйте развёрнутый сайт.

## Как пользоваться веб-приложением

Стартовый экран — хаб с двумя вариантами, **Отправить** и **Получить**, над живым демо-штрих-кодом, который можно сразу отсканировать другим телефоном. **Как это работает** (справа вверху) объясняет шаги, а в разделе **Под капотом** — формат и ёмкость кадра. Приложение следует системной светлой/тёмной теме.

### Отправка

1. Нажмите **Отправить** и выберите **Файл** или **Текст**. Файл выберите или перетащите в поле выбора; текст просто введите — подсказка ниже покажет его размер и сколько кадров он займёт. Текстовое сообщение приходит получателю как текст, готовый к копированию, а не как голый файл.
2. При желании раскройте **Добавить пароль** и введите его. Без пароля шифрования нет; если пароль задан, он понадобится получателю, чтобы открыть файл.
3. При желании раскройте **Дополнительно** и задайте **скорость кадров** — `100 мс` (быстро), `200 мс` (по умолчанию) или `400 мс` (медленно). Размер кадра не выбирается: каждый штрих-код — это кадр 608×608 px.
4. Нажмите **Создать код**. Сжатие автоматическое: журнал **Подробности** сообщает, был ли файл сжат (и насколько) или оставлен как есть — например, если это уже `.zip` или JPEG.
5. На экране **Готово к отправке** анимируется превью, а строка под ним показывает число кадров как «N + R» — исходные плюс восстановительные (см. ниже), — размер GIF и то, сжаты ли и зашифрованы ли данные. Для файлов больше 100 кадров появляется совет выбрать `400 мс`: так камере телефона проще поймать каждый кадр.
6. **Показать на весь экран** выводит штрих-код, масштабированный под экран, для камеры другого устройства. Экран не гаснет (Screen Wake Lock, где поддерживается); закрыть показ можно кнопкой ✕, клавишей Esc или жестом «Назад». **Поделиться** (есть там, где браузер умеет делиться файлами, то есть на телефонах) передаёт GIF в системное меню «Поделиться», а **Скачать** сохраняет его.

### Почему большие файлы передаются быстрее

GIF содержит N исходных кадров плюс около 25% дополнительных *восстановительных*, а **Показать на весь экран** вообще не зацикливается: один раз показывает N исходных кадров, а затем генерирует и показывает восстановительные, пока показ открыт (у однокадрового файла и у файла больше лимита кодирования в 4096 кадров восстановительных кадров нет, и показ зацикливает исходные). В любом случае декодеру — живому сканированию, фото или импорту GIF — достаточно поймать *любые* N кадров, исходных или восстановительных, в любом порядке, чтобы восстановить файл. Это устраняет старую проблему, когда сканирование быстро ловило почти всё, а потом застревало в ожидании одного-двух кадров, которые раз за разом пропускало.

### Получение

1. Нажмите **Получить** — сразу откроется камера. Наведите её на штрих-код; счётчик и полоса прогресса показывают «r / N кадров» — ранг, то есть число независимых кадров, пойманных из необходимых (при импорте GIF то же самое показано как «Ранг r / N»). Он растёт и на исходных, и на восстановительных кадрах и не меняется на кадре, который не несёт новой информации.
2. Нет камеры или доступ к ней запрещён? **Загрузить GIF или фото** открывает экран файлов, где можно выбрать GIF CimBar или **Снять кадры** — по одному фото на кадр, пока не наберутся все. Этот же экран открывается, если камеру не удалось запустить.
3. Если штрих-код зашифрован, экран разблокировки спрашивает пароль *после* того, как все кадры получены, — неверный пароль не означает повторного сканирования. Шифрование определяется автоматически по магическим байтам `CB 42` восстановленных данных, а сжатие — по заголовку кадра.
4. Полученный файл показывается с именем и размером: **Сохранить файл**, а также **Открыть** (для типов, которые браузер отображает безопасно, — PDF, изображения, простой текст, аудио/видео) и **Поделиться**, где браузер умеет делиться файлами. Полученное текстовое сообщение показывается как текст с кнопками **Копировать** и **Сохранить как .txt**.

Интерфейс веб-приложения доступен на английском, русском, украинском, турецком и грузинском (те же пять языков, что и в мобильном приложении); язык выбирается кнопкой в верхней панели хаба — выбор запоминается в браузере, а по умолчанию берётся язык браузера.

## Развёртывание веб-приложения

Веб-приложение развёртывается на `https://nfcarchiver.com/cimbar/` ручным workflow GitHub Actions **Deploy web app** (`.github/workflows/deploy-webapp.yml`) — той же схемы, что у веб-приложений NFC Archiver и Banana Split, делящих с ним бакет. Запускайте его на вкладке Actions с `master` (окружение `production` отклоняет другие ветки); отметьте *dry_run*, чтобы увидеть план загрузки, не трогая S3. Сборочная задача прогоняет веб-тесты, собирает ровно те файлы, которые загружает `index.html`, вписывает в страницу `<!-- cimbar-build:<sha> -->` и передаёт пакет задаче с учётными данными: она делает снимок текущего префикса, загружает скрипты, затем `index.html` (no-cache), инвалидирует CloudFront и проверяет публичный URL с помощью `web-app/tools/healthcheck.js`; при неудачной проверке снимок восстанавливается. Учётные данные приходят через GitHub OIDC (`AWS_DEPLOY_ROLE_ARN` в окружении `production`); бакет, префикс, дистрибуция и URL сайта — переменные окружения.

## Мобильное приложение (Android, iOS)

В каталоге `app/` — приложение на Flutter **CimBar Scanner** (application id `com.nfcarchiver.cimbar`), которое отправляет и принимает штрих-коды CimBar v2/v2.1 на телефоне. Оно кодирует текст или файл и показывает штрих-код на весь экран или делится им как GIF, а декодирует через импорт GIF, съёмку фото в приложении или живое сканирование камерой — так два телефона могут обменяться файлом вообще без сети.

**iOS:** то же приложение на Flutter собирается для iOS 14 и новее (`app/ios/`, bundle id `com.nfcarchiver.cimbar`, на экране — «CimBar»), включая Share Extension для отправки в него GIF из «Фото», «Файлов» и других приложений. Сборка проверяется в CI (*Build iOS (unsigned)*), но пока не подписывается и не распространяется. Чтобы запустить его на своём iPhone, откройте `app/ios/Runner.xcworkspace` в Xcode на Mac, укажите свою команду для обеих целей (Runner и ShareExtension) и свою App Group, затем запустите.

**Установка:** APK прикреплены к каждому [релизу на GitHub](https://github.com/mezinster/cimbar/releases); приложение подано в [F-Droid](https://f-droid.org/), который собирает его из исходников по рецепту `fdroid/com.nfcarchiver.cimbar.yml`. Единственное запрашиваемое разрешение — камера: ни интернета, ни хранилища. До 0.10.1 app id был `com.cimbar.scanner`: 0.11.0 устанавливается рядом как отдельное приложение, так что сохраните нужные декодированные файлы из старого и удалите его.

### Возможности

На нижней панели пять вкладок, в таком порядке (приложение открывается на «Импорт GIF»):

- **Отправить** — введите сообщение или выберите файл (до 4096 исходных кадров в штрих-коде), при желании задайте пароль и задержку кадров (100/200/400 мс), затем **Показать на экране** или **Поделиться GIF**. Показ выводит штрих-код на весь экран, не давая экрану погаснуть и на полной яркости: один раз N исходных кадров, затем восстановительные, пока показ открыт. «Поделиться GIF» собирает анимированный GIF (N исходных кадров + 25% восстановительных, до 500 исходных кадров) для системного меню «Поделиться». Кодирование идёт в фоновом изоляте и побайтно совпадает с веб-кодировщиком.
- **Импорт GIF** — выберите GIF-файл CimBar, при необходимости введите пароль, декодируйте и сохраните/отправьте исходный файл
- **Камера** — снимите фото в приложении (или выберите из галереи) для однокадрового штрих-кода либо используйте **Живое сканирование** для многокадрового анимированного
- **Файлы** — все декодированные файлы: открыть, сохранить или отправить
- **Инфо** (пятая вкладка, `SettingsScreen`) — переключатель режима отладки для разработчика (диагностический оверлей живого сканирования/logcat и кнопка захвата корпуса), выбор языка (английский, русский, турецкий, украинский, грузинский) и ссылки на политику конфиденциальности, лицензию и исходный код

Полученное **текстовое сообщение** (контейнер с именем `*.txt`, содержащий корректный UTF-8, до 1 МиБ, — то же соглашение, что и в текстовом режиме веб-приложения) показывается в карточке результата с кнопками «Копировать», «Поделиться» и «Сохранить как .txt», а не как голый файл.

### Живое сканирование камерой

Для многокадровых штрих-кодов CimBar (анимированных GIF):

1. Откройте вкладку **Камера**, при необходимости введите пароль и нажмите **Живое сканирование**, чтобы открыть камеру на весь экран.
2. Поместите штрих-код в прицельный квадрат; когда он найден, камера фиксирует фокус и экспозицию и снимает фиксацию, если штрих-код потерян на 2 секунды.
3. Если штрих-код найден, но декодируется плохо, появляются подсказки («ближе», «дальше», «не двигайтесь», «измените угол/освещение»).
4. Полоса прогресса показывает ранг (число пойманных независимых кадров) из необходимого числа; он растёт и на исходных, и на восстановительных кадрах, пойманных в любом порядке.
5. Когда ранг достигает нужного числа, приложение само расшифровывает и распаковывает данные (если нужно) и показывает результат.

Сканер собирает кадры по номеру/идентификатору восстановления и общему числу кадров из заголовка каждого кадра с помощью линейных комбинаций в GF(256), так что любые N независимых исходных или восстановительных кадров, пойманных в любом порядке, восстанавливают файл. Каждый кадр с камеры декодируется в фоновом изоляте, чтобы интерфейс оставался отзывчивым; занятый декодер просто пропускает следующий кадр, а не ставит его в очередь.

### Выпуск релиза

F-Droid собирает каждый релиз из закоммиченных исходников на теге `vX.Y.Z` и узнаёт о новых релизах, читая там `app/pubspec.yaml`, поэтому всё перечисленное ниже должно быть влито **до** запуска релиза:

1. Поднимите версию в `app/pubspec.yaml` — имя **и** `+versionCode` (код всегда растёт на единицу) — и в `web-app/index.html` (`data-version` и видимую `vX.Y.Z`).
2. Перенесите записи `[Unreleased]` из CHANGELOG под `## [X.Y.Z] — <дата>`.
3. Напишите changelog-файлы в `fastlane/metadata/android/<locale>/changelogs/` для всех пяти локалей (не более 500 символов каждый). Они называются по коду версии каждого **публикуемого APK**, а не по `+N` из pubspec: F-Droid собирает по APK на каждую ABI с кодом `10 × N + 1/2/3`, так что релизу `+190` нужны `1901.txt`, `1902.txt` и `1903.txt`.
4. `python3 tools/validate_store_metadata.py` и оба набора тестов проходят; влейте через PR.
5. Запустите workflow **Release** на `master` с той же версией; он откажется работать, если закоммиченный pubspec с ней не согласен. Он ставит тег `vX.Y.Z`, собирает APK/AAB с Flutter из `FLUTTER_VERSION` в `release.yml` (рецепт F-Droid читает ту же строку) и публикует релиз на GitHub.

Бот обновлений F-Droid сам замечает новый тег и открывает merge request с обновлением в fdroiddata; менять рецепт вручную нужно, только если меняются шаги сборки. Подробности — в `CLAUDE.md`.

Android-приложение переносит на Dart весь конвейер декодирования v2.1 из веб-приложения — арифметику GF(256), Reed-Solomon RS(255,191), кодирование и сборку восстановительных кадров, необязательную распаковку zlib, поиск угловых узоров, гомографическую модель сетки, баланс белого, решатель дрейфа, классификатор ячеек, расшифровку AES-256-GCM и слой захвата для живого сканирования/фото — всё с соответствующими модульными тестами, а также стенд синтетических искажений и бенчмарк на корпусе реальных снимков.

### Захват образца для корпуса

Конвейер декодирования проверяется и на реальных снимках с камеры, а не только на синтетических сценах. Чтобы добавить свой: включите «Инфо» → режим отладки, запустите живое сканирование, трижды коснитесь панели статуса, чтобы включить кнопку захвата, наведите камеру на штрих-код и нажмите значок камеры — в каталог документов приложения сохранится пара `capture_<ts>.png`/`.txt`. Как забрать эти файлы с устройства и превратить их в тест корпуса, описано в `app/test/fixtures/corpus/README.md`.

## Коррекция ошибок

Каждый кадр защищён кодом Reed-Solomon RS(255, 191): 64 байта коррекции на 255-байтовый блок, так что до 32 ошибочных байт на блок исправляются автоматически. Это делает GIF устойчивым к небольшим искажениям пикселей (например, при перекодировании или скриншотах), хотя передача без потерь всё же намного предпочтительнее.

Помимо коррекции RS внутри кадра, целиком потерянные или нечитаемые кадры покрываются описанными выше восстановительными кадрами: каждый из них — линейная комбинация исходных кадров в GF(256) с коэффициентами, выводимыми только из заголовка самого кадра (id файла, id восстановления, общее число), так что декодеру не нужен отдельный канал, чтобы знать, как его использовать. Любые N независимых кадров — исходных или восстановительных — дают все N исходных кадров методом Гаусса. Кодирование применяется только до 4096 исходных кадров (8,6 МБ после сжатия); большие файлы передаются без восстановительных кадров.

## Формат данных

Сначала файл оборачивается в небольшой контейнер (`[длина имени][имя][байты файла]`), затем сжимается zlib deflate, если это экономит хотя бы 5% размера (иначе пропускается — например, для уже сжатых медиа). Если задан пароль, (возможно, сжатый) контейнер затем оборачивается в фиксированный формат:

```
[CB 42 01 00]  4 байта   магическое число
[16 байт]      16 байт   соль (случайная для каждого файла)
[12 байт]      12 байт   IV   (случайный для каждого файла)
[переменная]   шифротекст + 16-байтовый тег AES-GCM
```

Вывод ключа: PBKDF2-SHA256, 150 000 итераций.

Внутри кадров GIF поток начинается с 4-байтового префикса длины `uint32` в big-endian (= длина данных до выравнивания кадров), чтобы декодер мог отбросить нулевое дополнение Reed-Solomon перед расшифровкой/распаковкой. Сжаты ли и зашифрованы ли данные, записано двумя битами в заголовке каждого кадра, а не в самих байтах формата.

## Запуск тестов

### Веб-приложение

Тестам нужен только Node.js (без npm). Запускайте из каталога `web-app/`:

```bash
cd web-app
sh tests/run_all.sh
```

Отдельные тесты:

```bash
cd web-app
node tests/test_tiles.js            # правила и генератор плиток
node tests/test_format.js           # спецификация формата, заголовок, упаковка битов
node tests/test_frame.js            # рендер/декодирование кадра, RS-кадрирование, сборщик
node tests/test_rateless.js         # восстановительные кадры в GF(256) и RatelessAssembler
node tests/test_rs.js               # коррекция Reed-Solomon
node tests/test_compress.js         # сжатие/распаковка zlib
node tests/test_goldens.js          # эталонные GIF против исходных данных
node tests/test_text_message.js     # контейнер текстового режима и распознавание UTF-8
node tests/test_pipeline_node.js    # полный конвейер GIF с префиксом длины
node tests/test_i18n.js             # строки интерфейса на пяти языках
node tests/test_browser_load.js     # скрипты страницы в одной общей глобальной области
node tests/test_page_logic.js       # скрипт страницы: фотосессия и завершение декодирования
node tests/test_markup.js           # статические проверки разметки index.html
node tests/test_router.js           # hash-маршрутизатор и переключение экранов
node tests/test_photo_geometry.js   # RGB/luma-буферы для декодирования фото
node tests/test_finder_locator.js   # поиск угловых узоров
node tests/test_cell_decode.js      # выборка и классификация ячеек
node tests/test_drift.js            # решатель дрейфа
node tests/test_photo_decode.js     # декодирование фото целиком
node tests/test_capture_policy.js   # политика захвата живого сканирования
node tests/test_scan_worker.js      # Web Worker сканирования
node tests/test_live_scan.js        # контроллер живого сканирования
node tests/test_healthcheck.js      # инструмент проверки после развёртывания
node tests/test_web_icons.js        # иконки, манифест и состав развёртывания
python3 tests/test_pipeline.py ../test-data/goldens/hello.gif 608   # оркестратор (шесть тестов) + проверка структуры GIF
python3 tests/test_gif.py path/to/output.gif 608                    # структура GIF (нужен Pillow)
```

### Android-приложение

Нужен Flutter SDK:

```bash
cd app
sh tests/run_all.sh           # никогда не голый `flutter test` — см. раздел Build в app/CLAUDE.md
```

Набор (452 теста) покрывает арифметику GF(256), кодирование/декодирование Reed-Solomon, слой формата v2/v2.1 (флаги заголовка, упаковка битов, RS-кадрирование, файловый контейнер, генерация и комбинирование коэффициентов), `RatelessAssembler`, слой декодирования с камеры (поиск узоров, гомографическая модель сетки, баланс белого, решатель дрейфа, классификатор ячеек, буферы YUV/ROI) на стенде синтетических искажений, крипто AES-256-GCM, сжатие zlib, `CapturePolicy`, `DecodeIsolate`, декодирование фото и импорт GIF, контроллер живого сканирования, отображение координат AR-оверлея, навигацию по полноэкранным маршрутам, бенчмарк времени декодирования и бенчмарк на корпусе реальных снимков.

## Совместимость

**Веб-приложение:** нужен современный браузер на HTTPS или `localhost` (этого требуют Web Crypto, доступ к камере и Web Workers); со страницы `file://` не работает (используйте локальный сервер выше). Кнопки «Поделиться» появляются только там, где браузер умеет делиться файлами, обычно на телефонах; экран не гаснет во время показа там, где поддерживается Screen Wake Lock.

**Android-приложение:** Android 7.0+ (API 24). Собрано на Flutter 3.44+.

**iOS-приложение:** iOS 14+; пока не распространяется (см. выше).

## Конфиденциальность

Ни одно из приложений ничего не собирает: никакой аналитики, трекеров и рекламы, а файлы, которые вы кодируете и декодируете, не покидают устройство. См. [PRIVACY_POLICY.md](PRIVACY_POLICY.md).
